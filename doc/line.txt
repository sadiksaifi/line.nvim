INTRODUCTION						*line-introduction*

line.nvim is an opinionated, minimal, and performant Neovim statusline plugin
written in pure Lua. This plugin provides a basic set of essential features
without overwhelming configuration options.

The statusline caches per-buffer data (paths, diagnostics, LSP clients, git
branch) and updates it from autocommands, so drawing it does no filesystem
or process work. The git branch is read from `.git/HEAD` without spawning
`git`.

==============================================================================
REQUIREMENTS						*line-requirements*

- Neovim >= 0.12.0
- A Nerd Font for the default icons

==============================================================================
INSTALLATION						*line-installation*

Using lazy.nvim~

Add this to your `lua/plugins/line.lua`:
>lua
    return {
      "sadiksaifi/line.nvim",
      opts = {}, -- or your custom options below
    }
<
With lazy.nvim, the `opts` table is passed to the plugin's `setup()` function.

Using vim.pack~

Add this to your `init.lua`:
>lua
    vim.pack.add({
      "https://github.com/sadiksaifi/line.nvim",
    })

    require("line").setup() -- or your custom options
<
==============================================================================
CONFIGURATION						*line-configuration*

The plugin works out of the box with sensible defaults. Pass options to
`setup()` to customize it. All options are typed for LSP completion. Calling
`setup()` again replaces the previous configuration. The defaults are:
>lua
    require("line").setup({
      root_markers = {
        ".git", ".vscode", ".editorconfig", "package.json", "deno.json",
        "pyproject.toml", "Cargo.toml", "go.mod", "composer.json", "Gemfile",
      },
      lsp = {
        ignored_clients = { "null-ls", "eslint" },
      },
      components = {
        mode = true,
        file_path = true,
        lsp = true,
        diagnostics = true,
        git = true,
        extension = true,
        progress = true,
        location = false,
        recording = false,
      },
      icons = {
        error = "󰅚",
        warn = "󰋽",
        info = "󰋼",
        hint = "󰌶",
        git = " ",
        modified = "●",
        readonly = "",
        busy = "◐",
      },
      theme = "default",
      colors = {},
    })
<
Annotate your config with the `LineConfig` type for completion:
>lua
    ---@type LineConfig
    local config = {
      theme = "rosepine",
      colors = {
        statusline = { fg = "#ffffff", bg = "#22223b" },
      },
    }
    require("line").setup(config)
<
==============================================================================
OPTIONS							*line-options*

root_markers						*line-root_markers*
	List of files or directories that identify the project root. Each
	marker is checked against all parent directories in order, so the
	first marker found wins. File paths are shown relative to the root.
	Files outside a project, or whose root is the home directory, are
	shown relative to the current directory or with `~`.

lsp.ignored_clients					*line-lsp-ignored_clients*
	LSP client names hidden from the statusline. These clients also do not
	trigger the loading spinner.
	Default: `null-ls`, `eslint`

components						*line-components-options*
	Enable or disable each statusline component:
	- mode: current mode (default: true)
	- file_path: file path with modified and readonly flags (default: true)
	- lsp: LSP clients, spinner while loading (default: true)
	- diagnostics: diagnostic counts (default: true)
	- git: git branch (default: true)
	- extension: file extension badge (default: true)
	- progress: |progress-message|s and 'busy' status (default: true)
	- location: line, column, and scroll percentage (default: false)
	- recording: register of the macro being recorded (default: false)

icons							*line-icons*
	Icons for components:
	- error, warn, info, hint: diagnostic severities
	- git: git branch
	- modified: buffer has unsaved changes
	- readonly: buffer is 'readonly' or not 'modifiable'
	- busy: buffer has 'busy' set

theme							*line-theme*
	Theme name. Unknown names fall back to "default" with a warning.
	- "auto": colors from the active colorscheme, updated on |ColorScheme|
	- "default": modern, elegant color palette
	- "rosepine": Rose Pine inspired colors
	- "catppuccin": Catppuccin inspired colors ("catpuccin" also works)
	- "tokyonight": Tokyo Night inspired colors
	- "gruvbox": Gruvbox inspired colors
	- "vscode": VS Code inspired colors
	- "dracula": Dracula inspired colors
	- "solarized": Solarized inspired colors
	- "boring": minimal, basic dark colors

colors							*line-colors*
	Overrides for specific colors of the selected theme. Each key takes a
	table with `fg` and `bg` as "#rrggbb" strings. Keys you omit keep the
	theme's values. Keys: statusline, normal, insert, visual, replace,
	command, select, shell, terminal, file, file_dir, diagnostic_error, diagnostic
	(warnings), diagnostic_info, diagnostic_hint, lsp, git, extension,
	separator, inactive.

==============================================================================
COMPONENTS						*line-components-overview*

Left side:
- Current mode
- File path relative to the project root, with modified and readonly flags.
  Terminal buffers show the exit code after the process ends.

Right side, in order:
- Macro recording (opt-in)
- Progress messages and 'busy' status
- Diagnostic counts (errors, warnings, info, hints)
- LSP status: client names, or a spinner with the loading clients and their
  average percentage while a server reports progress
- Git branch, or the short commit hash on a detached HEAD
- Cursor location (opt-in)
- File extension badge. Special buffers show their 'buftype'. Files without
  an extension show their 'filetype'.

Inactive windows show only the file path, using |hl-LineInactive|.

Special buffers~
- Terminals show the running command and, after it exits, its exit code.
- Quickfix and location lists show their title. line.nvim sets
  |g:qf_disable_statusline| so the quickfix ftplugin does not replace the
  statusline. Set it to 0 before `setup()` to keep the default.
- Plugin windows ('buftype' set) show their 'filetype' in the badge.
- URI buffers such as `oil:///path` show the scheme and a short path.

Narrow windows~					*line-responsive*
When the line does not fit the window, content is dropped in this order
until it fits:
  1. Cursor location
  2. LSP clients
  3. Directory names in the path shorten to one letter
  4. Git branch
  5. Progress
  6. Extension badge
  7. Diagnostics
The mode shows a short label (N, I, V) below 60 columns. Branch names and LSP
client lists longer than 30 characters end with "…".

==============================================================================
HIGHLIGHT GROUPS					*line-highlights*

line.nvim defines these groups from the theme and |line-colors|, and
redefines them on every |ColorScheme| event:

	*hl-LineStatusline*	Statusline background and default text
	*hl-LineSeparator*	Separator between right side components
	*hl-LineModeNormal*	Normal and Operator-pending mode
	*hl-LineModeInsert*	Insert mode
	*hl-LineModeVisual*	Visual modes
	*hl-LineModeReplace*	Replace modes
	*hl-LineModeCommand*	Command-line mode and prompts
	*hl-LineModeSelect*	Select modes
	*hl-LineModeShell*	Shell mode
	*hl-LineModeTerminal*	Terminal mode
	*hl-LineFile*		File name and cursor location
	*hl-LineFileDir*	Directory part of the file path
	*hl-LineLsp*		LSP clients and progress
	*hl-LineDiagnosticError*	Error count
	*hl-LineDiagnostic*	Warning count and macro recording
	*hl-LineDiagnosticInfo*	Info count
	*hl-LineDiagnosticHint*	Hint count
	*hl-LineGit*		Git branch
	*hl-LineExtension*	File extension badge
	*hl-LineInactive*	Statusline of inactive windows

==============================================================================
API							*line-api*

require("line").setup({opts})				*line.setup()*
	Set up the statusline. See |line-configuration|.

require("line").refresh()				*line.refresh()*
	Reapply theme colors to the highlight groups.

require("line").render()				*line.render()*
	Return the statusline string for the window in |g:statusline_winid|.
	line.nvim sets 'statusline' to call this function.

==============================================================================
HEALTH							*line-health*

Run `:checkhealth line` to check the Neovim version, whether `setup()` ran,
the selected theme, and whether another plugin replaced 'statusline'.
